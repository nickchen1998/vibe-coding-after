# 《Vibe Coding 時代的 DevOps 挑戰》隨書程式碼

> **Locust × Loki × Grafana，從負載測試到系統監控的完整實戰**
> 陳柏翰 著／博碩文化

這裡放的是書中每一章的**可執行範例**：被壓測的靶場服務、Locust 腳本、LGTM 監控堆疊的 `docker-compose.yml`、三大框架的監控中介層，以及儀表板與告警的佈建檔。

書談的是 AI 讓程式碼變得廉價之後、「功能完成」與「生產就緒」之間那道鴻溝：用 **Locust** 這把長矛主動攻擊自己的系統、逼出弱點，再用 **Grafana Loki** 這面盾牌讓系統開口說話。這個倉庫，就是那把矛與那面盾的實體。

## 怎麼用

**一章一個目錄，每個目錄都能獨立跑起來。** 你不需要從第 3 章照順序做到第 12 章，也不需要先跑完前一章才能開始這一章——想練 LogQL 就直接進 `程式碼/第09章/`，它自備一整套 Loki + Alloy + Grafana 與日誌來源。

**每個目錄都有自己的 `README.md`**，寫明該章的檔案角色、事前準備與完整的重現步驟。根目錄這一份只負責指路，實際動手請翻該章的 README。

**第 1、2 章沒有程式碼**：那兩章談的是觀念與環境準備（Claude Code、Poetry、Docker 的安裝），照書操作即可。實作從第 3 章開始。

## 事前準備

| 需要 | 版本 | 用在哪 |
| --- | --- | --- |
| Python | 3.10 以上 | 全部章節 |
| Docker Desktop（或 Docker Engine + Compose） | 近期版本 | 第 5、7、8、9、10、11、12 章 |

套件安裝各章 README 都有列出該章需要的最小集合。書中使用 Poetry 管理環境（第 2 章有教），但你要用 `venv` + `pip` 也完全沒問題——各章 README 的安裝指令都以 `pip` 撰寫。

## 兩個閱讀慣例

**檔案樹裡的標記。** 各章 README 的檔案樹會標注每個檔案的身分：`【你新增】` 是你要親手建立（或直接從這裡取用）的檔案，`【工具寫入】` 是程式執行後自動產生的產物，不必也不該手動編輯。

**書中的數字，是本機實測的真實結果。** 所有 Locust 戰報、延遲數據與 Grafana 截圖都來自實際執行，不是編出來的。也因為靶場刻意埋了隨機延遲與失敗率，你在自己機器上重現時，數字會與書中略有出入——這是正常的，重點在於**趨勢與量級**是否一致，而不是小數點後幾位。

## 遇到問題

各章 README 末尾多半附有常見卡關點。若你確定是這裡的程式碼有誤（而非環境差異），歡迎開 [Issue](../../issues) 回報，請一併附上你的作業系統、Python 版本與完整錯誤訊息。
